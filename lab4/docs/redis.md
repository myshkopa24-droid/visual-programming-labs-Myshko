# Описание интеграции n8n с Redis

## 1. Развертывание Redis

Для организации локального хранилища данных был запущен официальный Docker-контейнер с Redis версии 7. Запуск производился с пробросом стандартного порта `6379`:

```bash
docker run -d --name redis -p 6379:6379 redis:7

```

Для проверки доступности сервера из консоли хоста использовалась команда:

```bash
docker exec -it redis redis-cli ping

```

Успешный ответ `PONG` подтвердил корректность работы инстанса.

## 2. Настройка Credentials в n8n

В панели управления n8n созданы учетные данные (Credentials) для подключения к Redis:

* **Host:** `host.docker.internal` (либо IP-адрес шлюза Docker `172.17.0.1` для обеспечения стабильного сетевого моста между контейнерами).


* **Port:** `6379`.


* **Password:** поле оставлено пустым (так как контейнер запущен без авторизации).



## 3. Реализация Workflow №1: Создание и чтение ключа (`flow-09-redis.json`)

Первый сценарий предназначен для записи данных в Redis и их последующей проверки:

1. **Manual Trigger** — инициирует запуск цепочки вручную.


2. **Redis (Set / Set the value of a key in redis)** — записывает в базу данных ключ, сформированный из фамилии студента на английском языке (например, `myshko`), и задает произвольную строковую текстовую нагрузку.


3. **Redis (Get / Get the value of a key from Redis)** — выполняет чтение созданного ключа для верификации записанного значения.



## 4. Реализация Workflow №2: Удаление ключа и проверка (`flow-10-redis.json`)

Второй сценарий демонстрирует очистку данных и проверку состояния ключа:

1. **Manual Trigger** — запуск сценария.


2. **Redis (Delete / Delete a key from Redis)** — удаляет ранее созданный ключ из хранилища Redis.


3. **Redis (Get / Exists)** — выполняет попытку чтения или проверки ключа для подтверждения того, что он успешно удален из базы данных и больше не существует.
